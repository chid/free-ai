How Does Google Release Models So Quickly?

Why the jump from Gemini 3.6 to 3.7 to 3.8 happens in weeks rather than years — and what actually changes under the hood.

⚡ The Short Answer

Yes, it is overwhelmingly post-training, reinforcement learning, distillation, and test-time compute. No AI lab retrains multi-billion-dollar base models from scratch every month. Instead, foundation models serve as a reusable "encyclopedic brain," while rapid iterative releases tune how the model plans, reasons, and self-checks.

Pre-Training vs. Post-Training: The Paradigm Shift

Pre-Training (The Foundation)

3–6+ Months
  • Trained on trillions of tokens across the open web, books, and code.
  • Massive TPU clusters running for months from random weight initialization.
  • Builds the raw knowledge base and linguistic grammar.
  • Extremely expensive ($50M–$200M+); done infrequently.

Post-Training & RL (The Modern Frontier)

1–3 Weeks
  • Warm-started from an existing stable checkpoint.
  • Reinforcement Learning with Verifiable Rewards (RLVR) in code sandboxes.
  • Distillation of complex thinking trajectories from larger Pro models into Flash.
  • Inference-time search algorithms and customizable "thinking budgets."

The 5 Engines Behind Rapid Cadence

01 / RLVR

Reinforcement Learning with Verifiable Rewards

Instead of manually scoring text, Google runs models in simulated sandboxes with bash shells, unit tests, and compilers. When code passes tests or solves a bug, the model receives positive mathematical reinforcement. These RL loops take days, not months.

02 / DISTILLATION

Frontier-to-Flash Distillation

Google uses frontier research models running massive multi-path search to generate millions of optimal reasoning traces. Flash models are trained directly on those successful trajectories, inheriting breakthroughs in weeks.

03 / TEST-TIME COMPUTE

Inference-Time Scaling

Much of the jump between models like 3.7 and 3.8 isn't weight scale—it's giving the model time to "think" before emitting output. Reasoning tokens allow the model to backtrack and critique itself before making a tool call.

04 / WARM STARTS

Continual Domain Pre-Training

Rather than starting with random noise, engineers take the latest checkpoint and expose it to dense domain tokens (e.g. security CVEs for Flash Cyber, or new programming language documentation).

05 / INFRASTRUCTURE

TPU Fleets & Automated Sandboxes

Google owns its custom hardware stack (TPU v5p, Trillium TPU v6e). Without GPU cloud queue bottlenecks, they can train dozens of alignment and RL runs concurrently and benchmark them within hours.

The Takeaway: Pre-training gives an AI model its encyclopedic memory (grammar, vocabulary, facts). Post-training teaches it how to behave as an autonomous software engineer (planning, self-testing, error recovery). Rapid iteration between minor versions is Google optimizing that second layer.
